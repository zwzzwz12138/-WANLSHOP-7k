技术架构篇——Uniapp 多端多商户商城的工程化底座
多商户商城的复杂度与架构挑战
运营版多商户商城需要同时服务平台方、入驻商家、用户、达人、主播等多类角色。每个商家拥有独立的商品、订单、装修、营销和数据。叠加短视频社区种草、直播带货、阶梯拼团等新场景，系统复杂度远超单商户商城。传统单体架构难以承载，必须采用前后端分离、模块化、可插拔的工程架构。该系统以 Uniapp 为前端统一层，一套代码编译至微信小程序、H5、Android App、iOS App；后端提供 RESTful API 与 WebSocket，支撑多商户、短视频、直播、分销、阶梯拼团等业务。

Uniapp 前端：多端一致与差异化适配
Uniapp 基于 Vue 语法，通过条件编译处理各端差异。小程序端使用微信登录、微信支付、订阅消息、小程序直播组件；H5 端使用浏览器路由、H5 支付、分享链接；App 端集成原生支付、推送、扫码、直播推拉流。系统抽象统一请求层、Token 管理、权限路由、埋点 SDK，使商城首页、分类、详情、购物车、订单、个人中心、商家入驻、短视频流、直播间、拼团页复用同一套业务逻辑。短视频流采用上下滑动切换，需优化视频预加载、懒加载、内存回收与首帧速度。直播页面包含视频区、主播信息、商品列表、优惠券、评论互动、下单入口。阶梯拼团页需实时展示不同人数对应的价格阶梯与成团进度。

后端架构与多商户数据模型
后端可采用 ThinkPHP、Laravel、Hyperf 或 Java Spring Boot 构建。核心数据模型包括：平台、商户、店铺、商品、SKU、订单、会员、优惠券、拼团、阶梯拼团、秒杀、分销、佣金、结算单、短视频、直播、评论、点赞、收藏、话题、达人。系统通过商户 ID 与店铺 ID 实现数据隔离，确保不同商户之间互不干扰。权限体系基于 RBAC，覆盖平台管理员、商户、店长、运营、客服、财务、达人、主播等角色，支持菜单、按钮、数据范围三级控制。

短视频、直播与阶梯拼团模块的架构位置
短视频社区作为独立模块，支持上传、转码、审核、推荐、评论、点赞、收藏、分享。视频可挂载商品、优惠券、拼团、直播预约。直播模块可接入微信小程序直播、腾讯云直播、阿里云直播或第三方推拉流。直播间支持商品挂载、优惠券发放、实时互动、下单转化。阶梯拼团模块支持多阶梯价格配置：拼团人数越多，价格越低；或不同人数对应不同优惠。前端实时计算当前参团人数与下一阶梯差价，激励用户分享拉人。三者与商品、订单、支付、会员、分销深度耦合，形成“内容—流量—交易—裂变”闭环。

模块化与插件化设计
系统将多商户、短视频、直播、阶梯拼团、分销、秒杀、DIY 装修等拆分为独立模块。每个模块拥有独立路由、数据表、后台菜单和前端页面，可按需启用或停用。插件机制支持第三方支付、物流、短信、AI 客服、直播服务等扩展。运营版进一步优化了模块间通信与事件机制，降低耦合，提升可维护性。企业可二次开发，对接 ERP、CRM、WMS，新增行业功能。
